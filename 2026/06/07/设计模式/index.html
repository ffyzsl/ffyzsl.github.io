设计模式详解

发表于 2026-06-07

1. 什么是设计模式？

你装修房子，不会从烧砖开始——你会用现成的设计方案：承重墙在哪、水电怎么走、插座留几个。这些是前人踩过无数坑后总结出来的成熟经验。

设计模式就是软件工程里的”装修方案”——针对常见的编程问题，前人总结的、可复用的解决方案。

三个分类

分类 解决的问题 代表模式
创建型 怎么创建对象最灵活 工厂、单例、建造者
结构型 类和对象怎么组合更合理 适配器、装饰器、代理
行为型 对象之间怎么协作更优雅 策略、观察者、模板方法

策略模式怎么解决

策略模式的核心思想：把变化的”算法”封装成独立的策略类，运行时可以自由切换。

策略模式的核心

策略模式做到了面向对象设计中的开闭原则：对扩展开放（加新策略类），对修改关闭（不用改已有的 Order 类）。

3. 工厂模式家族

工厂模式分三种，按复杂度递增排列：简单工厂 → 工厂方法 → 抽象工厂。

3.1 简单工厂（Simple Factory）

把对象的创建逻辑集中到一个地方。

简单工厂的好处是：创建逻辑集中管理，调用方不需要知道具体类的构造细节。但它还不算真正的”设计模式”——只是一个好的编程习惯。

3.2 工厂方法（Factory Method）

如果每种产品的创建逻辑更复杂，简单工厂的 if-else 又会膨胀。工厂方法让每个具体类都有对应的工厂。

工厂方法的核心：把”创建产品”这个步骤延迟给子类决定。Logistics 基类知道该怎么做规划，但具体用什么运输工具由子工厂决定。

3.3 抽象工厂（Abstract Factory）

当需要创建一系列相关联的对象时，用抽象工厂。

三种工厂怎么选

10. 模式对比速查

模式 一句话 典型场景
策略 把 if-else 拆成独立的策略类 会员折扣、支付方式、排序算法
简单工厂 集中管理对象创建 根据配置创建不同数据库连接
工厂方法 每个产品一个工厂，延迟创建 物流系统（陆运/海运）
抽象工厂 创建一整套相关对象 UI 主题切换、跨平台数据库驱动
单例 全局只允许一个实例 数据库连接池、配置管理器
适配器 不兼容的接口之间加转换层 老系统对接新接口、第三方库替换
观察者 一对多通知：状态变了自动告诉订阅者 股票推送、事件总线、消息队列
装饰器 嵌套包装增加功能 日志加时间戳、咖啡加配料
代理 控制对真实对象的访问 图片懒加载、远程服务本地代理
模板方法 骨架固定，细节留给子类 数据导出、测试框架

11. 总结

设计模式的核心思想不是背代码，而是学会把”变化的部分”和”不变的部分”分开：

  • 策略模式：变化的”算法”抽出去
  • 工厂模式：变化的”创建方式”抽出去
  • 适配器模式：变化的”接口”隔离开
  • 观察者模式：变化的”通知对象”灵活增减
  • 装饰器模式：变化的”附加功能”层层叠加
  • 模板方法模式：变化的”步骤细节”留给子类

看到一段代码里有大量 if-else、变量在多个地方被修改、或者每次加功能都要改核心类——这些就是设计模式的应用时机。

但记住最重要的原则：KISS（Keep It Simple, Stupid）。能用一个函数搞定的，不要引入五个类。设计模式是工具，不是目的。
