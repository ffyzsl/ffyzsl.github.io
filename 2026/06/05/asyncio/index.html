1. 什么是 asyncio？

写一个爬虫，要抓取 10 个网页。每个网页响应需要 1 秒。如果用同步代码：

10 个页面，串行请求，耗时 10 秒。但问题在于：等待网络响应的那 1 秒里，CPU 什么也没做，只是在等。

asyncio 的解决思路：在等待 A 页面响应的间隙，去请求 B 页面；在等待 B 页面响应的间隙，去请求 C 页面。最终所有请求几乎同时发出，全部完成只需要略多于 1 秒。

同步 vs 异步的本质区别

程序里的大部分”慢”，不是在 CPU 计算上，而是在 IO 上——网络请求、文件读写、数据库查询。asyncio 专门解决这种 IO 密集型场景。

2. 核心概念

在深入 API 之前，先搞清楚四个基本概念。

2.1 协程（Coroutine）

用 async def 定义的函数就是协程函数，调用它返回一个协程对象。

调用协程函数不会执行里面的代码。协程必须被事件循环驱动才能运行。

2.2 事件循环（Event Loop）

事件循环是 asyncio 的大脑。它维护一个任务队列，不断切换执行各个协程。哪个协程在 await（等待 IO），事件循环就跳过它，去执行另一个准备好的协程。

asyncio 使用的是单线程并发模型。同一时刻只有一个协程在跑，但等待 IO 时会让出 CPU。

2.3 Task（任务）

Task 是对协程的包装。把协程包装成 Task 并提交给事件循环后，它就进入调度队列，开始执行。

Task 有三种状态：PENDING（等待调度）、RUNNING（正在执行）、DONE（已完成）。

2.4 Future（未来结果）

Future 是一个”占位符”——代表一个尚未完成的计算的最终结果。Task 是 Future 的子类。大多数时候你直接和 Task 打交道。

4. asyncio.run() —— 程序的唯一入口

run() 做三件事：

  1. 创建一个新的事件循环
  2. 运行协程直到完成
  3. 关闭事件循环

注意：run() 不能在一个已有事件循环运行的线程中调用。在 Jupyter Notebook、已经运行的 FastAPI 服务器中不可以直接使用 asyncio.run()，应该直接用 await。

10. asyncio.to_thread() —— 把同步代码桥接进异步

很多现有的库不支持 async——比如 requests、time.sleep、os.path 的大多数函数。如果在协程中直接调用这些同步函数，会阻塞整个事件循环。to_thread() 把同步函数放到一个单独的线程中运行，不阻塞异步代码。

输出：

三个 time.sleep 在三个独立线程中执行，总的等待时间为最长的那个（3 秒），而不是 2+1+3=6 秒。

12. asyncio.Queue —— 生产者-消费者模式

Queue 是异步编程中最常用的数据结构之一。多个生产者往队列放数据，多个消费者从队列取数据，两者解耦。
