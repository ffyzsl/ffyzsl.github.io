WebSocket详解

发表于 2026-06-04

1. WebSocket 是什么？

想象你在等一个重要的快递。如果用 HTTP 的方式：

这就是 HTTP 轮询（Polling）——客户端不停地问，服务器被动应答。每问一次都要敲一次门、开一次门，非常低效。

WebSocket 的做法是：你和快递员之间拉了一根专用电话线。电话接通后，任何一方都可以随时说话，不需要反复拨号。

HTTP vs WebSocket

HTTP WebSocket
连接方式 请求→响应→断开 一次握手，持久连接
通信方向 客户端主动，服务器被动 全双工，双方可随时发消息
头部开销 每次请求几百字节 每帧仅 2-14 字节
延迟 毫秒到秒级 微秒到毫秒级
适用场景 REST API、页面浏览 聊天、实时推送、协作编辑、游戏

一句话总结

WebSocket 是建立在 TCP 之上的全双工持久连接协议。一次握手后，客户端和服务器可以随时互相发送消息，不需要反复建立连接。

2.3 握手成功后

握手完成，TCP 连接不会断开。之后的所有通信使用二进制帧（Frame）格式，不再是 HTTP 文本报文。

3. 数据帧：WebSocket 怎么传输数据

握手之后的一切通信，都使用帧（Frame）来传输。你不需要手动构建帧——SDK 帮你处理——但理解帧的结构有助于排查问题和理解性能特性。

3.1 帧的简化结构

每帧头部最少 2 字节，最多 14 字节。对比 HTTP 每次请求几百字节的头部，WebSocket 的带宽开销极小。

3.2 帧类型（Opcode）

Opcode 名称 作用
0x1 Text 传输 UTF-8 文本
0x2 Binary 传输二进制数据（图片、音频等）
0x8 Close 关闭连接
0x9 Ping 心跳检测——“你还活着吗？”
0xA Pong 心跳响应——“我还活着！”
0x0 Continuation 分片消息的后续帧

3.3 掩码（Mask）

客户端发往服务器的数据必须使用掩码——每帧用 4 字节随机密钥和载荷做 XOR 运算。这是为了防止一种叫”缓存污染攻击”的安全问题。

服务器发给客户端的数据不需要掩码。

你需要关心这些吗？

在日常开发中，不需要。Python 的 websockets 库、FastAPI 的 WebSocket 支持、浏览器的 WebSocket API 都自动处理了握手、帧封装、掩码、Ping/Pong。你只需要调用 send() 和 recv()。

8. 生产环境考量

8.1 心跳（Ping/Pong）

WebSocket 连接在长时间无数据传输时，可能被中间的网络设备（NAT、代理、负载均衡器）断开。心跳机制定期发 Ping，告诉中间设备”这个连接还活着”。

8.4 安全：认证与 wss

10. 总结

核心概念

概念 解释
WebSocket TCP 之上的全双工长连接协议
握手 HTTP 升级请求 → 101 Switching Protocols
帧 握手后通信的最小单位（2字节头起步）
accept() 服务器接受连接（FastAPI 中必须第一个调用）
send_text() / receive_text() 收发文本消息
Ping/Pong 协议层心跳，保持连接存活
WebSocketDisconnect 客户端断开的异常
广播 向所有连接的客户端发送消息

WebSocket vs 其他实时通信方案

方案 原理 延迟 复杂度 适用场景
短轮询 定时 AJAX 请求 高 低 对实时性要求极低
长轮询 请求挂起等响应 中 中 兼容老旧浏览器
SSE 服务器单向推送 低 低 服务器→客户端单向通知
WebSocket 全双工长连接 极低 中 聊天、协作、实时数据

简单口诀： 只要服务器推客户端，用 SSE；需要双向实时通信，用 WebSocket；只需要间歇查询，用普通 HTTP 即可。
